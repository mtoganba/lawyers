# SAQ — Юридическая экспертиза

Рабочий макет раздела правового обеспечения для юридической экспертизы аудиторских документов.

Целевой репозиторий: https://github.com/mtoganba/lawyers. В других репозиториях этого проекта изменения не допускаются.

## Что реализовано

- Реестр объектов по образцу вкладки «Контроль качества» ВГА: «Мои действия», «В работе ЮЭ», «Ожидаем аудитора», «Все объекты», поиск и выгрузка CSV.
- «Юридическая экспертиза 2» — основной этап; «Юридическая экспертиза 3» — заключительный этап.
- Одна карточка на объект и аудиторское мероприятие; юридическая экспертиза 2 и 3 показаны отдельными карточками этапов внутри объекта.
- Назначение и замена ответственного юриста руководителем этапа. При замене сохраняется причина и история.
- Создание проекта заключения назначенным юристом, направление руководителю на рассмотрение, возврат с замечаниями и завершение рассмотрения.
- Рабочее пространство заключения: «Форма заключения», «Документы на экспертизе», «Электронная форма», Word, печать и выбор передачи комплекта.
- Предлагаемые проверочные листы с выбором направлений: бюджетное законодательство, бухгалтерский учёт. В новом комплекте дополнительные направления не выбраны; их подключает юрист по материалам дела.
- Ответы «Соответствует», «Есть замечания», «Не применимо», «Не проверено».
- Замечания с привязкой к документу, пункту, норме НПА и рекомендуемому исправлению.
- Проверка полноты заполнения перед завершением или передачей на доработку.
- Тестовая повторная передача с сохранением прежних документов и оценок.
- Электронная форма юридического заключения в блоке результата: просмотр, скачивание DOCX и печать.
- Локальные приложения и текстовая выгрузка замечаний.
- История действий и сохранение в localStorage браузера.
- Адаптивная компоновка для узких экранов.

## Ограничения макета

ВГА не подключён: документы и передача на доработку демонстрационные. Переключатель «Демо» позволяет пройти действия руководителя и юриста; ограничения действий работают локально и не заменяют серверную авторизацию. Общего серверного хранилища и многопользовательской работы нет. Файлы и черновики сохраняются только в браузере. Даты сроков тестовые, нормативные сроки автоматически не рассчитываются. Критерии и процесс требуют согласования с правовым подразделением.

Для результата используется рабочий шаблон юридического заключения. Просмотр и DOCX формируются из одной модели данных карточки. Это не утверждённая нормативная форма и не подписанный документ. Электронное подписание не реализовано.

## Запуск

Статические файлы в корне репозитория образуют готовый сайт без сборки. Нужны `app.js`, `core.js`, `workflow.js`, `styles.css`, `workspace.css`, `logo.svg`; для печатных форм — `print-forms.js` и включённая библиотека `docx-9.6.1.js`. Для локального просмотра:

```sh
python3 -m http.server 8000
```

Затем откройте http://localhost:8000. Не открывайте HTML как `file://`: браузеру требуется HTTP для загрузки ES-модулей.

Проверки основной логики:

```sh
npm test
```

Для формирования Word используется включённая в репозиторий библиотека docx 9.6.1 (MIT), лицензия — `DOCX-LICENSE.txt`. Подключение к внешним сервисам для создания документа не требуется.

Для GitHub Pages можно опубликовать корень ветки `main` этого же репозитория. Отдельный репозиторий для размещения создавать не нужно.

## Визуальный образец

Структура реестра, карточки объекта и рабочего пространства заключения адаптирована из предоставленного архива ВГА: `QualityRegistry.tsx`, `QualityAssignmentPanel.tsx`, `QualityDocumentWorkspace.tsx` и соответствующий раздел `audit-layout.css`. Из архива не переносятся учётные записи, серверные настройки и нормативная форма заключения контроля качества. Источники ВГА не изменяются.
